# 路径兼容修复记录

时间：2026-09-29。

## 问题

旧版本将 `materials.file_path` 保存为运行环境绝对路径。Windows 本地示例为 `D:\...\uploads\1\file.md`，Docker Linux 示例为 `/app/uploads/1/file.md`。同一数据库在另一环境启动时，下载接口按绝对路径查文件会失败并返回 404。

## 修复

- `app/db.py`
  - 新增 `material_relative_path()`，将新旧路径规范化为上传根目录相对路径。
  - 新增 `resolve_material_file()`，按当前 `UPLOAD_ROOT` 解析真实文件，并要求结果位于 `UPLOAD_ROOT/<class_id>` 内。
  - 初始化种子材料改为保存 `1/seed-sdd-guide.md` 这类相对路径。
- `app/__init__.py`
  - 上传新材料时保存相对路径，不再保存 `path.resolve()` 的绝对路径。
  - 下载和删除统一通过 `resolve_material_file()` 解析，路径越界或缺失返回 404。
- `scripts/migrate_material_paths.py`
  - 支持预览和 `--execute`。
  - 正式执行前使用 SQLite Backup API 完整备份数据库。
  - 只迁移能安全转换且文件存在、班级目录与 `class_id` 一致的记录。
- `tests/test_acceptance.py`
  - 覆盖 Windows 绝对路径、Linux 绝对路径、相对路径兼容。
  - 覆盖本班下载 200、未登录 401、跨班 404、路径穿越拒绝。
- OpenSpec
  - 已更新 `add-auth-rbac-class-knowledge` 与 `add-protected-material-download` 的 design/spec。
